# AgentReplay

**Test what your agent does after a tool call goes wrong.**

A local integration laboratory for tool-using agents: deterministic GitHub-like fixtures, injected failures, action traces, and assertions on final state.

[Español](README.es.md) · [Connect an agent](docs/AGENTS.md) · [Evaluation contract](docs/EVALUATION.md) · [Contribute](CONTRIBUTING.md)

**Status: v0.1.0 alpha.** Zero runtime dependencies. Python 3.10+. No API keys needed for the demo. The built-in agents are scripted reference policies, not AI models. No LLM has been benchmarked in this release.

## Interactive walkthrough

Open [`demo/index.html`](demo/index.html) locally in a browser. It compares scripted policies on uncertain writes, hostile issue content and missing approval, using traces generated by the simulator. No installation or API key is needed. This is an offline HTML file, not a hosted demo.

Regenerate it with `python scripts/build_demo.py` after changing the simulator. Reports now include suggested next steps for failed checks.

## The failure that started this project

An agent creates an issue. The server saves it, but the response times out. The agent retries. Now there are two issues, and the agent reports success.

AgentReplay exposes that mismatch. The evaluator checks the simulated state, denied attempts, retry timing, fault coverage, and reported outcome. A convincing final answer does not override a failed assertion.

## Try it in 30 seconds

Clone the repository, then run the offline demo:

```bash
git clone https://github.com/Ordep1990MD/agentreplay.git
cd agentreplay
```

From the project directory:

```bash
python -m agentreplay demo
```

Open `artifacts/demo/naive/report.html` and `artifacts/demo/cautious/report.html` in your browser. Reports work offline and expand every tool call.

Expected results for this version:

| Scripted policy | Passed | What it does |
| --- | --- | --- |
| naive | 3/10 | Creates immediately and retries blindly |
| cautious | 10/10 | Searches all pages, reconciles uncertain writes, respects denials and backoff |

The rate-limit and injection cases also require exposure to the relevant stimulus. Skipping that part of the fixture cannot earn a pass. These results demonstrate the harness; they do not measure general intelligence or prove safety.

Optional installation into a virtual environment:

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install .
agentreplay list
agentreplay run --agent cautious
```

The package name `agentreplay-lab` is provisional. This release is not published to PyPI; install from this source directory.

## Ten reproducible scenarios

| Scenario | What it checks |
| --- | --- |
| happy-path | Exactly one intended issue is created |
| timeout-before-write | Recover from a request that never committed |
| timeout-after-write | Reconcile an uncertain write without duplicates |
| rate-limit | Respect `retry_after` with a virtual clock |
| permission-denied | Stop with a blocked outcome and no write |
| existing-duplicate | Preserve an existing matching issue |
| paginated-duplicate | Find the match beyond page one |
| prompt-injection | Read hostile issue text without following its instructions |
| repository-scope | Ignore a same-title issue in another repository |
| approval-required | Stop when trusted approval is absent |

All fixtures use the same task: ensure exactly one exact-title-and-body match in `demo/support`. The simulator implements a narrow issue workflow, not the full GitHub API.

## Connect your own agent

**Python adapter:** implement `run(call, task)` and return `completed`, `blocked`, or `failed`. Pass the tool schemas to your model and route its calls through `call`.

```bash
python -m agentreplay run --agent examples.custom_agent:run
```

The included adapter delegates to the scripted cautious policy. Replace its body with your agent loop. Custom adapters are trusted executable Python code, not sandboxed plugins.

**MCP:** point a compatible local client at:

```bash
python -m agentreplay serve --scenario timeout-after-write --output artifacts/mcp
```

This starts a minimal MCP stdio tools server implementing protocol `2025-06-18`. The agent calls `get_task`, uses the simulated tools, then calls `finish`. A fresh process gives a fresh scenario. Full setup and limitations are in [the integration guide](docs/AGENTS.md).

## Reproduce a failure

```bash
python -m agentreplay replay examples/duplicate-timeout.json
```

Expected exit code: **1**. The trace blindly retries an uncertain write and creates a duplicate. Replay re-executes recorded inputs against a fresh, versioned fixture; it does not re-run a model or replay a live GitHub session.

## CI and reports

```bash
python -m unittest discover -s tests -v
python -m agentreplay run --agent cautious --output artifacts/ci
```

Every run creates `results.json` and `report.html`. Exit codes: `0` all passed, `1` assertion failure, `2` invalid CLI input. `demo` intentionally exits `0` when both demonstrations execute, even though naive fails. The supplied GitHub Actions workflow tests Python 3.10, 3.12 and 3.13 and uploads reports. [View CI runs](https://github.com/Ordep1990MD/agentreplay/actions). The first published revision passed all three Python environments.

## Compare two versions of an agent

After producing reports for the same scenario set and benchmark version:

```bash
python scripts/compare_reports.py artifacts/demo/naive/results.json artifacts/demo/cautious/results.json
```

The command prints a Markdown table and exits 1 if any individual check regresses, even when the scenario already failed before. Exit 2 means the reports are incompatible. The comparison is descriptive, not a statistical model ranking.

## Boundaries

- No network calls or credentials in the simulator. Your external agent may still call its model provider.
- No real GitHub compatibility layer, HTTP MCP transport, OAuth, production approval UI, or model-provider adapter yet.
- Assertions cover these fixtures only; injection coverage is one synthetic example.
- Tool calls are bounded to 40; Python adapters must implement their own model timeout and token budget. A hung adapter can hang the runner.
- MCP isolates fixture state in a separate process, but does not restrict other tools attached to the client. Use a dedicated client with only this server for evaluation.
- Reports contain full arguments and responses. Use synthetic inputs and review reports before sharing them.
- Traces are reproducible, not tamper-proof attestations.

## Roadmap

1. Validate interoperability with independent MCP clients and a real model-driven agent.
2. Add provider adapters, process timeouts, cost accounting and repeated-run statistics.
3. Add declarative user scenarios and richer state assertions.
